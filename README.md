# toukei_tashikame

『**Pythonで学ぶ！統計学入門** — シミュレーションで確かめる、推定・検定・回帰・ベイズ・因果推論』の教材コードです。本に出てくるコードは、全部ここにあります。

95%信頼区間の「95%」が何を指すのかは、定義文を10回読むより、10,000回まわして数えるほうが速い。この本はそういう進め方をします。その10,000回を、あなたの手元で実際にまわせる形にしたのがこのリポジトリです。

## まず1本動かす

必要なのは [uv](https://docs.astral.sh/uv/) だけです（Python も uv が入れます）。

```bash
git clone https://github.com/ykus4/toukei_tashikame
cd toukei_tashikame
uv sync
uv run python examples/ch00/hello_confidence_interval.py
```

こう出れば準備完了です。

```
0.9477 ± 0.0044
```

μ=50 の母集団から20個の標本を引いて信頼区間を作る、を10,000回くり返して、そのうち何本が真の μ を包んだかを数えた結果です。**95%に近い数字が出ましたが、ぴったり95%ではありません。** その ± が、数え上げそのものの誤差です。

## このリポジトリの約束

**同じ数字が出ます。** すべての生成器が `seed` を取り、`np.random.default_rng` だけを使います。`np.random.seed` は1行も書いていません。あなたの手元と本の紙面で、同じ数字が出るはずです。

**数字には必ず誤差がつきます。** `0.9477 ± 0.0044` の ± は、10,000回という有限回で数えたことによる揺れです。あなたの環境で `0.9491` が出ても、それは実装の違いではありません。この幅より小さい差は、数え直しただけで動きます。

**本の数字は、このコードから出ています。** 逆ではありません。ライブラリのバージョンが上がって数字が変わったら、直すのは本のほうです。

## 中身の作り

```
examples/ch00 … ch18/   本文と1対1に対応するスクリプト。本のコードはここからの抜粋
src/toukei_tashikame/   何度も使う道具。本文で import しているのはこれ
notebooks/              触って遊ぶための場所
tests/                  手書き実装と scipy / statsmodels の照合
```

`src/toukei_tashikame/` にあるのは、毎回書き直すと本題が隠れてしまうものだけです。

| モジュール | 何をするか |
|---|---|
| `datasets` | 合成データ生成器。全部シード固定で、**真の値を返り値に持つ** |
| `sim` | 「10,000回まわして数える」の基盤。確かめる段はすべてここを通る |
| `describe` | 記述統計。`ddof` と分位点の補間を引数に出す |
| `plots` | 図の共通スタイル。色は役割で決まる |
| `estimate` | 最尤推定・ブートストラップ・信頼区間 |
| `testing` | 各検定の手書き実装。結果が**仮定を持ち回る** |
| `power` | 検出力・サンプルサイズ設計 |
| `regression` | OLSを正規方程式から・残差診断・VIF |
| `glm` | IRLS。ロジスティックとポアソンが同じ関数 |
| `bayes` | グリッド近似・共役更新・Metropolis-Hastings |
| `causal` | IPW・傾向スコア・DID・RDD・操作変数 |

逆に、本文が「**手で書く**」と宣言した実装は、その節の `examples/` に直接書いてあります。読んでいる節のコードが `import` の向こうに隠れることはありません。

### 真の値を持っている、ということ

合成データから始めるのには理由があります。

```python
from toukei_tashikame import datasets

d = datasets.ab_test(p_a=0.030, lift=0.10, seed=0)
d.p_b        # 0.033  ← 合成データだけが知っている真の値
d.b.mean()   # 0.0328 ← 観測されたCVR。推定の対象であって、答えではない
```

信頼区間が当たったか外れたかは、真の値を知らなければ数えられません。実データでそれができないのは道具の限界ではなく、真の値が隠れているという状況そのものの帰結です。だからこの本は、まず答えを知っている世界で道具の挙動を確かめます。

## うまくいかないとき

**数字が本と少し違う** — `±` の幅の中なら正常です。それより大きく違う場合は、`uv sync` をやり直してください（`uv.lock` が同じライブラリを入れます）。

**図の日本語が豆腐（□□□）になる** — 日本語フォントが見つかっていません。macOS なら標準で入っています。Linux では `sudo apt install fonts-noto-cjk` を。

**`ModuleNotFoundError: pymc`** — 第16章と第18章 case3 です。`uv sync --extra slow` を実行してください。

**動かない・数字がおかしい** — [Issues](https://github.com/ykus4/toukei_tashikame/issues) に書いてください。本の誤りとして直すべきものかもしれません。

## 自分のデータで使う

`datasets` の生成器を、自分のデータに差し替えれば、そのまま道具として使えます。

```python
from toukei_tashikame import testing

res = testing.t_ind(group_a, group_b)   # 既定は Welch
print(res)                              # 統計量・p値と一緒に「仮定」が出ます
```

`testing` と `causal` の結果は、推定値だけでなく**それが立っている仮定**を持っています。印字すると仮定も出ます。p値だけを取り出して仮定を忘れる、ということをしにくくするための作りです。
